# Contributing to Nexora Manager

Thank you for considering a contribution to Nexora Manager.

## Before you start

- Read the [project documentation](/docs/README.md).
- Search existing issues before opening a new one.
- Keep changes focused and avoid unrelated refactors.
- Do not commit secrets, signing material, tokens, API credentials, or generated private files.
- Preserve GPL-3.0 licensing and required upstream attribution.

## Bug reports

Use the repository's **Bug report** issue template. Include reproducible steps, relevant logs, Android/app versions, and screenshots when useful.

## Feature requests

Use the **Feature request** issue template. Describe the problem, the proposed behaviour, alternatives considered, and why the change belongs in Nexora Manager.

## Code contributions

1. Create a branch from the current development branch.
2. Make the smallest coherent change that solves the issue.
3. Build and test the affected area.
4. Run formatting/static checks used by the project.
5. Submit a pull request with a clear description and validation evidence.

## Project identity

Nexora Manager is maintained as an independent project. Do not add upstream project logos, social links, badges, or branding as Nexora identity.

Some internal code and dependencies still originate from upstream open-source components. Keep technical references where they are required for compatibility, licensing, or attribution until those components are deliberately migrated.

## Licensing

Contributions are made under the repository's GPL-3.0 license. Do not remove license notices, copyright notices, or provenance required by the license.

## Translations

Translation infrastructure is being separated from upstream services. Until a Nexora-owned translation service is configured, translation changes should be submitted directly through the repository.
